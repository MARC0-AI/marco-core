# MARCO Engineering Principles

## 1. User trust first

MARCO must make important actions understandable and controllable.

## 2. Outcome over output

The goal is successful task completion, not simply generating text or commands.

## 3. Permission by design

Sensitive actions must pass through the permission system.

## 4. Modular architecture

Core components should communicate through clear interfaces rather than tightly coupled implementations.

## 5. Provider independence

MARCO should not depend permanently on a single AI model provider.

## 6. Testable by default

New behavior should be accompanied by automated tests.

## 7. Secure by default

Secrets, credentials, and sensitive user data must never be committed to source control.

## 8. Observable execution

Important actions should produce structured events and results that can be inspected and audited.

## 9. Documentation matters

Architecture and behavior should be documented as the system evolves.

## 10. Keep the core simple

Avoid unnecessary dependencies and abstractions until they solve a real problem.
